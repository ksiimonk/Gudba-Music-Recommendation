# Логика рекомендаций

## Общий пайплайн

Каждый запрос рекомендаций проходит последовательные этапы:

```
Загрузка профиля → Загрузка событий → Кандидаты → Скоринг → Фильтрация → Реренкинг → Сохранение → Ответ
```

## 1. Холодный старт

Если у пользователя нет профиля (не пройден онбординг), рекомендации строятся исключительно на популярности треков:

```
score = (popularity_score / 100) × 20
```

Треки сортируются по убыванию score. Фильтрация и реренкинг не применяются. Explanation: "Популярен среди слушателей".

## 2. Онбординг-профиль

При прохождении онбординга пользователь выбирает:
- Любимые жанры (genre_ids)
- Любимых артистов (artist_ids)
- Стартовые треки (track_ids)
- Контексты прослушивания (contexts)

Эти данные сохраняются в user_preferences и user_profiles. Используются для генерации кандидатов и скоринга.

## 3. События

Система собирает поведенческие события:
- **play** — трек был прослушан (понижает score при повторных запросах)
- **like** — трек понравился (влияет на recent_interest)
- **dislike** — трек не понравился
- **skip** — трек пропущен (исключается из будущих рекомендаций на 24ч)
- **open** — плейлист открыт

В scoring engine учитываются события за последние 24 часа.

## 4. Генерация кандидатов

Все треки из БД являются кандидатами. Дополнительные фильтры не применяются на этапе генерации — все фильтры работают на этапе scoring.

## 5. Формула scoring

Каждый трек получает оценку от 0 до 100 на основе четырёх факторов:

### genre_match (макс 40 баллов)

```
matching_genres = количество жанров трека, совпадающих с любимыми жанрами пользователя
total_genres = общее количество жанров трека
genre_score = (matching_genres / total_genres) × 40
```

### artist_match (макс 25 баллов)

```
artist_score = 25, если artist.id трека есть в любимых артистах пользователя
artist_score = 0, иначе
```

### popularity (макс 20 баллов)

```
popularity_score = (track.popularity_score / 100) × 20
```

### recent_interest (макс 15 баллов)

Если хотя бы один жанр трека совпадает с жанрами треков, которые пользователь лайкнул за последние 24 часа:

```
interest_score = 15
```

### Итоговая оценка

```
total_score = genre_score + artist_score + popularity_score + interest_score
```

## 6. Фильтрация

После скоринга применяются следующие фильтры:

| Фильтр | Действие |
|--------|----------|
| Пропущенные (skip) | Трек полностью удаляется из выдачи, если он был пропущен за последние 24ч |
| Сыгранные (play) | score × 0.7 (понижение на 30%) |

## 7. Реренкинг (диверсификация)

Чтобы избежать однообразия в выдаче:

- Не более **2 треков** одного артиста в топ-10
- Не более **3 треков** одного жанра подряд

Треки, нарушающие эти ограничения, пропускаются, и вместо них выбираются следующие по score.

## 8. Генерация объяснений

Каждый рекомендованный трек получает текстовое объяснение на русском:

| Условие | Explanation |
|---------|-------------|
| genre_score > 0 и artist_score > 0 | "Совпадает с твоими любимыми жанрами и артистами" |
| genre_score > 0 | "Совпадает с твоими любимыми жанрами" |
| artist_score > 0 | "Похож на артистов из твоего профиля" |
| interest_score > 0 | "Учитывает твои недавние лайки" |
| Холодный старт | "Популярен среди слушателей" |

## 9. Рекомендации плейлистов

Для плейлистов используется аналогичный подход. Профиль плейлиста строится на основе его треков:

- **dominant_genres**: топ-жанры по частоте в треках
- **dominant_artists**: топ-артисты
- **avg_popularity**: средний popularity_score треков

Scoring для плейлистов:

| Фактор | Макс | Описание |
|--------|------|----------|
| genre_overlap | 40 | Пересечение жанров плейлиста с любимыми жанрами |
| artist_overlap | 25 | Пересечение артистов плейлиста с любимыми |
| liked_track_genres_boost | 20 | Совпадение с жанрами лайкнутых треков |
| popularity | 15 | Средняя популярность треков плейлиста |

## 10. Ограничения

- **Нет коллаборативной фильтрации** — рекомендации основаны только на профиле пользователя и его собственных событиях
- **Нет обработки натурального языка** — тексты песен не анализируются
- **Статический скоринг** — веса факторов фиксированы (40/25/20/15)
- **Холодный старт для новых треков** — если трек не имеет popularity_score, его score будет низким
- **Отсутствие real-time обновлений** — профиль обновляется только при повторном онбординге
